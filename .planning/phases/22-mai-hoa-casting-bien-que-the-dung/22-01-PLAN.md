<algorithm_pinned_from_adr_0006>
ADR-0006 §3 + §4 locks the casting convention verbatim. Implement EXACTLY this:

```
// Inputs (all u8):
//   lunar_year_branch : 0..=11  (Tý=0, Sửu=1, ..., Hợi=11) — the BRANCH index, not sexagenary pair
//   lunar_month       : 1..=12  (canonical month only; leap-month indexing deferred per ADR-0006 §2)
//   lunar_day         : 1..=30
//   chi_hour_index    : 0..=11  (Tý=0, ..., Hợi=11); DEC-0017 early-Tý/late-Tý split is the CALLER's concern, not cast_mai_hoa's

sum_base = (lunar_year_branch + lunar_month + lunar_day) as i32   // upper-trigram sum
sum_full = sum_base + chi_hour_index as i32                        // lower-trigram + moving-line sum

upper_idx = ((sum_base - 1) % 8) + 1   // 1..=8  → TienThienTrigram::ALL[upper_idx - 1]
lower_idx = ((sum_full - 1) % 8) + 1   // 1..=8  → TienThienTrigram::ALL[lower_idx - 1]
dong_hao  = ((sum_full - 1) % 6) + 1   // 1..=6  (1 = bottom line)

upper = TienThienTrigram::ALL[(upper_idx - 1) as usize]
lower = TienThienTrigram::ALL[(lower_idx - 1) as usize]
chu_que = compose(upper, lower)   // KingWenHexagram
```

**Worked boundary proof (ADR-0006 §4) — the CRIT-2 test cites this verbatim:**
Inputs `(8, 8, 8, 8)`:
- `sum_base = 24` → `((24-1) % 8) + 1 = (23 % 8) + 1 = 7 + 1 = 8` → Tiên Thiên #8 = **Khôn** ☷ (NOT Kiền)
- `sum_full = 32` → `((32-1) % 8) + 1 = (31 % 8) + 1 = 7 + 1 = 8` → Tiên Thiên #8 = **Khôn** ☷
- moving line: `((32-1) % 6) + 1 = (31 % 6) + 1 = 1 + 1 = 2` → động hào = 2
- Result: upper Khôn + lower Khôn = King Wen **#2 (Thuần Khôn)**, động hào 2.

The naïve `24 % 8 = 0 → coerced to 1 = Kiền` would compose King Wen #1 (Thuần Kiền) — a COMPLETELY DIFFERENT hexagram. The boundary test asserts #2, NOT #1.
</algorithm_pinned_from_adr_0006>
