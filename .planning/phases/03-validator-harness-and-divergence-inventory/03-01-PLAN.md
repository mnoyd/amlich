Create `crates/amlich-core/tests/khcbppt_stars.rs` with these components:

1. **File header comment** explaining this is a KHCBPPT star validator, run with `cargo test -- --nocapture` for full reports, and that this is INVENTORY ONLY (no corrections).

2. **Helper function `star_quality_to_str`** mapping `StarQuality::Cat` -> "cat", `StarQuality::Hung` -> "hung", `StarQuality::Binh` -> "binh".

3. **Test `verify_jd_epoch_against_khcbppt_dated_entries`** (STR-02):
   - This test verifies the 28-star JD epoch (jd.rem_euclid(28)) by checking 3+ golden dataset entries that have known star-to-date mappings.
   - Select the first 5 entries from the golden dataset (they have star assignments computed from get_day_info).
   - For each, call `get_day_info(solar_day, solar_month, solar_year)`, extract `day_fortune.stars.day_star`.
   - Handle `Option<DayStar>`: if `None`, record mismatch "expected star X, got NONE".
   - Compare `day_star.name` against `entry.expected_star_name` and `day_star.index` against `entry.expected_star_index`.
   - Use collect-then-assert pattern. If mismatches found, `eprintln!` a "JD EPOCH DIVERGENCE REPORT" with warning that all star validations are suspect.
   - Assert `mismatches.is_empty()`.

4. **Test `validate_stars_against_golden`** (STR-01, STR-03):
   - Iterate ALL 233 entries from `load_golden_dataset()`.
   - For each entry, call `get_day_info()`, extract `day_fortune.stars.day_star`.
   - Compare three fields against golden entry:
     a. `day_star.name` vs `entry.expected_star_name` (STR-01 covers FixedByChi via coverage)
     b. `day_star.index` vs `entry.expected_star_index`
     c. `star_quality_to_str(&day_star.quality)` vs `entry.expected_star_quality` (STR-03)
   - Handle `None` day_star: record all three as mismatches with "got NONE".
   - Use collect-then-assert pattern with `eprintln!` report header: "STAR DIVERGENCE REPORT (N mismatches across 233 entries)".

5. **Test `report_star_rule_sparsity`** (supplementary, per research recommendation):
   - Iterate all 233 entries, count how many have zero `matched_rules` entries with category "FixedByCanChi", "ByYear", "ByMonth", or "ByTietKhi".
   - `eprintln!` a summary: "Star rule sparsity: N/233 entries have no contextual star rules".
   - This test always passes (informational only). It documents the coverage gap.

  <name>Task 2: Create khcbppt_taboos.rs validator</name>
  <files>crates/amlich-core/tests/khcbppt_taboos.rs</files>
  <action>
Create `crates/amlich-core/tests/khcbppt_taboos.rs` with these components:

1. **File header comment** explaining KHCBPPT taboo validator, run with `--nocapture`, INVENTORY ONLY.

2. **Helper function `compare_taboo_sets`** taking solar_date (&str), expected (&[String]), actual (&[DayTaboo]), and &mut Vec<String> for mismatches:
   - Convert expected to `HashSet<&str>` (the rule_ids from golden entry).
   - Convert actual to `HashSet<&str>` by extracting `t.rule_id.as_str()` from each DayTaboo.
   - Compute set difference both ways:
     a. MISSING = in expected but not in actual (golden says should fire, impl doesn't)
     b. EXTRA = in actual but not in expected (impl fires, golden doesn't have it)
   - Push formatted mismatch strings for any MISSING or EXTRA entries.

3. **Test `validate_taboos_against_golden`** (TAB-01, TAB-02, TAB-03, TAB-04):
   - Iterate ALL 233 entries from `load_golden_dataset()`.
   - For each entry, call `get_day_info(entry.solar_day, entry.solar_month, entry.solar_year)`.
   - Call `compare_taboo_sets(&entry.solar_date, &entry.expected_taboos, &info.day_fortune.taboos, &mut mismatches)`.
   - After iteration, `eprintln!` the "TABOO DIVERGENCE REPORT" if mismatches exist.
   - Assert `mismatches.is_empty()`.
   - This single test covers TAB-01 (tam_nuong entries are in expected_taboos), TAB-02 (nguyet_ky entries), TAB-03 (sat_chu entries across 12 months), TAB-04 (tho_tu entries across 12 months) because the golden dataset includes all taboo rule_ids that should fire.

4. **Test `validate_taboo_coverage_by_rule`** (supplementary):
   - After running the full comparison, count how many unique rule_ids appear across all 233 entries in both golden and actual.
   - `eprintln!` a summary: "Taboo rules seen in golden: {set}. Taboo rules seen in impl: {set}."
   - This test always passes (informational). It helps verify all 4 taboo types (tam_nuong, nguyet_ky, sat_chu, tho_tu) actually appear in the dataset.
