<objective>
Implement the OnceLock-backed IChing corpus loader + lookup API + black-box integration tests.

Purpose: This is the CODE half of ICH-01. Plan 21-01 authored the 64-entry `hexagrams.json` corpus; this plan implements the loader that embeds it via `include_str!`, parses it once on first access through a `OnceLock` cache, enforces the `hao_tu` length invariant (6 for #3..64, 7 for #1/#2 per ADR-0005 §2), NFC-normalizes every Vietnamese text field (RIT-08 precedent), and exposes `get_hexagram(KingWenHexagram) -> Option<&'static HexagramEntry>` + `all_hexagrams() -> &'static [HexagramEntry]`. This mirrors the v1.5 `rituals/corpus.rs` pattern exactly (Phase 11) — the template is proven across three corpus milestones.

Output: `iching/corpus.rs` (loader + lookup API), `iching/mod.rs` (registration), `tests/iching_corpus_integration.rs` (ICH-01 verification).
</objective>

```rust
const CORPUS_JSON: &str = include_str!("../../data/rituals/<file>.json");

#[derive(Debug, Deserialize)]
struct FileEnvelope {
    #[serde(rename = "$schema_version")]
    schema_version: String,
    entries: Vec<RitualEntry>,
}

static CORPUS: OnceLock<Vec<RitualEntry>> = OnceLock::new();

pub fn all_rituals() -> &'static [RitualEntry] {
    CORPUS.get_or_init(|| {
        // parse + assert schema_version + normalize_and_validate each entry
    }).as_slice()
}

fn normalize_and_validate(mut entry: RitualEntry) -> RitualEntry {
    // NFC-normalize every String field; assert source_id
    entry.title_vi = nfc(&entry.title_vi);
    // ...
}

fn nfc(s: &str) -> String {
    if is_nfc(s) { s.to_string() } else { s.nfc().collect() }
}
```

<!-- The locked HexagramEntry fields that need NFC normalization at load: -->
HexagramEntry text fields requiring NFC: `vi_name`, `thoai_tu`, every String in `hao_tu`, `cat_hung`.
Reserved Option<String> fields (also NFC if present, but None in v1.7): `vi_name_en`, `thoai_tu_en`, `hao_tu_en`.

<!-- The hao_tu length invariant (ADR-0005 §2 — loader-enforced, NOT serde): -->
- king_wen_index 1 or 2: hao_tu.len() == 7
- king_wen_index 3..=64: hao_tu.len() == 6
- Panic on violation (fail-fast; corpus is compile-embedded so a parse failure is a build-time bug).

**Tests to implement:**

1. **`lookup_all_64_indices_succeed` (SC1):** For each `kw` in `1..=64u8`, construct `KingWenHexagram::new(kw).unwrap()`, call `get_hexagram(kw_hex)`, assert `is_some()`. 3. **`corpus_trigram_identity_matches_composition_table` (authoring-error catcher):** For each index 0..=63 (King Wen #1..64), verify the corpus entry's trigram IDENTITY matches the composition table's trigram pair. Since both `TienThienTrigram` and `HauThienTrigram` serialize to the same snake_case variant names by identity, convert both to their serde JSON string form and compare:
   ```rust
   let (tt_upper, tt_lower) = COMPOSITION_TABLE[i];
   let tt_upper_name = serde_json::to_string(&tt_upper).unwrap(); // e.g. "\"kien\""
   let entry = get_hexagram(KingWenHexagram::new((i+1) as u8).unwrap()).unwrap();
   let ht_upper_name = serde_json::to_string(&entry.upper_trigram).unwrap();
   assert_eq!(tt_upper_name, ht_upper_name, "trigram identity mismatch at King Wen #{}", i+1);
   // same for lower
   ```
   This catches any authoring error where the corpus JSON's trigram variant doesn't match the composition table. NOTE: this comparison is on the serde NAME (identity), NOT the discriminant value — CRIT-3 isolation is preserved because we never convert between types, we compare serialized names.

4. **`every_entry_carries_reviewer_signature` (SC2):** For every entry, assert `entry.reviewer` contains the substring `"ExternalReviewPending"`. Assert `entry.pending_review.is_some()` (the DeferralMarker). Assert the `reviewer` and `pending_review` fields are consistent (both reference `external-kinh-dich-reviewer` and `2026-12-31`).

5. **`every_text_field_is_nfc_normalized` (SC3):** For every entry, assert `is_nfc(&entry.vi_name)`, `is_nfc(&entry.thoai_tu)`, `is_nfc(&entry.cat_hung)`, and `is_nfc(line)` for every line in `entry.hao_tu`.

6. **`load_is_lazy_and_idempotent` (SC4):** Call `all_hexagrams()` twice, assert both return the same pointer (`as_ptr()` equality). This proves OnceLock lazy caching.
