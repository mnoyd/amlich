Author the 64-hexagram Ngô Tất Tố corpus JSON + the accompanying provenance audit ledger.

Purpose: This is the DATA half of ICH-01. The locked `HexagramEntry` schema (Phase 20, ADR-0005) is frozen; this plan authors all 64 corpus entries against it. The structural fields (`king_wen_index`, `vi_name`, `upper_trigram`, `lower_trigram`) are deterministically known from the classical King Wen sequence (the `COMPOSITION_TABLE` in `iching/schema.rs` already encodes the trigram pairs + Vietnamese names). This mirrors the Phase 17 rituals closure pattern (60 entries all ExternalReviewPending when no independent reviewer is available).

Output: `data/iching/hexagrams.json` (64 entries) + `data/iching/provenance_audit.md` (64-row ledger).

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct HexagramEntry {
    pub king_wen_index: KingWenHexagram,        // u8 newtype, 1..=64
    pub vi_name: String,                         // Vietnamese hexagram name (NFC)
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub vi_name_en: Option<String>,              // reserved; OMIT in v1.7 corpus
    pub upper_trigram: HauThienTrigram,          // serializes to snake_case: "kien".."khon"
    pub lower_trigram: HauThienTrigram,          // serializes to snake_case
    pub thoai_tu: String,                        // judgment text (deferred)
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub thoai_tu_en: Option<String>,             // reserved; OMIT
    pub hao_tu: Vec<String>,                     // 6 entries (#3..64); 7 for #1 & #2
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub hao_tu_en: Option<Vec<String>>,          // reserved; OMIT
    pub cat_hung: String,                        // auspiciousness verdict (deferred)
    pub reviewer: String,                        // ExternalReviewPending(...) free-text marker
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub pending_review: Option<DeferralMarker>,  // Some(DeferralMarker) when deferred
}
```

HauThienTrigram serializes to (snake_case variant names — same names as TienThienTrigram, different discriminants):
`"kien"`, `"doai"`, `"ly"`, `"chan"`, `"ton"`, `"kham"`, `"can"`, `"khon"`

DeferralMarker shape (reused verbatim from almanac/fengshui/golden.rs:85-95):
```json
{"reason": "...", "expected_review_date": "...", "assigned_to": "..."}
```

COMPOSITION_TABLE (schema.rs:182-247) — index 0 = King Wen #1. Each row comment carries the Vietnamese name:
```
#1  (Kien, Kien)   Thuần Kiền    #2  (Khon, Khon)  Thuần Khôn
#3  (Kham, Chan)   Truân         #4  (Can, Kham)   Mông
#5  (Kien, Kham)   Nhu           #6  (Kham, Kien)  Tụng
... (all 64 in schema.rs:182-247)
```
The trigram IDENTITY maps 1:1 between Tiên Thiên and Hậu Thiên variants by NAME:
TienThienTrigram::Kien → upper_trigram: "kien"; ::Khon → "khon"; ::Kham → "kham"; ::Chan → "chan"; ::Can → "can"; ::Doai → "doai"; ::Ly → "ly"; ::Ton → "ton".

<design_decisions>
**Corpus deferral strategy (AF-05 compliance):**
Claude does NOT have verbatim access to Ngô Tất Tố's *Kinh Dịch Trọn Bộ*. Per AF-05 ("never silently filled from another translator"), the interpretive text fields (`thoai_tu`, `hao_tu`, `cat_hung`) are honestly deferred. Every entry carries:
- `pending_review: {"reason": "...", "expected_review_date": "2026-12-31", "assigned_to": "external-kinh-dich-reviewer"}`
- `reviewer`: the free-text `ExternalReviewPending(reason="..."; expected_review_date="..."; assigned_to="...")` marker
- Text fields: explicit placeholder strings prefixed `[PendingExternalReview — ...]` (grep-able, honest, non-empty)

This is the exact pattern from Phase 17 rituals closure (60/60 entries ExternalReviewPending when no independent reviewer is available in this Claude execution). The structural fields that ARE deterministically known (king_wen_index from the sequence; vi_name from the classical names in the composition table; upper/lower_trigram from the composition table trigram pairs) ARE populated — the corpus is a faithful skeleton, not hollow.

The `vi_name` values come from the COMPOSITION_TABLE comments in schema.rs (e.g. "Thuần Kiền", "Truân", "Mông", "Nhu", ...). These are the standard Hán-Việt hexagram names, not Ngô Tất Tố's unique contribution.
</design_decisions>

**Step 1 — Derive structural fields from COMPOSITION_TABLE.**
Read `crates/amlich-core/src/iching/schema.rs:182-247` (the `COMPOSITION_TABLE` const array). For each index i (0..=63), King Wen number = i+1:
- `king_wen_index`: the 1-based King Wen number (1..=64).
- `vi_name`: the Vietnamese hexagram name from the table row's trailing comment (e.g. #1 → "Thuần Kiền", #3 → "Truân", #11 → "Thái"). Use the Hán-Việt name exactly as written in the comment (strip the pinyin in parentheses and the "— trigram above trigram" suffix).
- `upper_trigram`: the Hậu Thiên variant name matching the IDENTITY of `COMPOSITION_TABLE[i].0` (the first element of the tuple). Map by variant name: `Kien→"kien"`, `Khon→"khon"`, `Kham→"kham"`, `Chan→"chan"`, `Can→"can"`, `Doai→"doai"`, `Ly→"ly"`, `Ton→"ton"`.
- `lower_trigram`: same mapping for `COMPOSITION_TABLE[i].1` (the second element of the tuple).

**Step 2 — Populate deferred text fields with honest placeholders.**
For EVERY entry (all 64), set:
- `thoai_tu`: `"[PendingExternalReview — thoái từ (彖辭 judgment): Ngô Tất Tố Kinh Dịch Trọn Bộ source text pending external review]"`
- `cat_hung`: `"[PendingExternalReview — cát hung (吉凶 verdict): Ngô Tất Tố source reading pending external review]"`
- `hao_tu`: an array of placeholder strings. For #3..=64: exactly 6 entries (sơ hào, nhị hào, tam hào, tứ hào, ngũ hào, thượng hào). For #1 Kiền: exactly 7 entries (the 6 above + dụng cửu). For #2 Khôn: exactly 7 entries (the 6 above + dụng lục). Each placeholder: `"[PendingExternalReview — hào từ {position}: Ngô Tất Tố source text pending]"` where `{position}` is the Vietnamese line name.

**Step 3 — Populate reviewer + deferral marker.**
For EVERY entry, set:
- `reviewer`: `"ExternalReviewPending(reason=\"Ngô Tất Tố Kinh Dịch Trọn Bộ interpretive text not available in this Claude execution; AF-05 forbids filling from another translator\"; expected_review_date=\"2026-12-31\"; assigned_to=\"external-kinh-dich-reviewer\")"`
- `pending_review`: `{"reason": "Ngô Tất Tố Kinh Dịch Trọn Bộ interpretive text (thoai_tu, hao_tu, cat_hung) pending external review per AF-05", "expected_review_date": "2026-12-31", "assigned_to": "external-kinh-dich-reviewer"}`

**Step 4 — Omit reserved fields.**
Do NOT include `vi_name_en`, `thoai_tu_en`, or `hao_tu_en` in any entry (they are `Option<T>` with `skip_serializing_if` — absent in JSON means `None`). This mirrors RIT-13 `body_en` reservation discipline.

**IMPORTANT — NFC normalization:** Write all Vietnamese text in NFC (composed) form. The diacritics in names like "Thuần Kiền", "Thuần Khôn" must be precomposed (U+1EA6 etc.), NOT decomposed combining sequences. The loader (Plan 02) will NFC-normalize at load, but the source data should be canonical.

**JSON format:** 2-space indentation, UTF-8, no BOM. Ensure valid JSON (no trailing commas, proper escaping of the `\"` inside the reviewer free-text string — in JSON, the inner quotes must be escaped as `\"`).
