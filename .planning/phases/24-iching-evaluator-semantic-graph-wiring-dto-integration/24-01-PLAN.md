<critical_constraints>
- **Sibling-newtype discipline (locked, non-negotiable):** `IChingQuery` is a NEW newtype — NOT a `ConsultationIntent::IChing` variant. Mirrors the v1.6 `DailyFlyingStarLayout` sibling-to-`FlyingStarLayout` precedent. Adding a `ConsultationIntent::IChing` variant would force ~25-43 call-site `Copy`-break churn across the codebase (per `.planning/research/ARCHITECTURE.md:436-440`). The existing `ActionId::IChing` enum variant (Phase 20-03) is fine — it identifies the action, not the query payload.
- **CRIT-3 isolation preserved:** NO `From` impls between `TienThienTrigram` / `HauThienTrigram` / `KingWenHexagram`. The composition table + `compose()` are the ONLY bridges. No `FlyingStar` reference anywhere in `evaluator.rs`. No Phase 23 cross-link code — `build_direction_cross_link` is NOT imported here.
- **MOD-7 / Tier-0 (no birth data):** The evaluator MUST work with `personal_input: None`. The `ActionEvaluator` adapter's `personal_input` parameter is ignored for the baseline IChing path. The `IChingQuery` constructor takes only `chi_hour_index` + `question_vi` (optional) — no `BirthInput` field. Calling `to_bazi_input()` on a missing `PersonalReasoningInput` would crash; do not route through that path.
- **Per-step evidence (CRIT-6):** Emit AT LEAST two primitive `ReasoningEvidenceEnvelope` instances with DISTINCT source_ids — one carrying `SOURCE_MAI_HOA_DICH_SO` (casting + derivation) and one carrying `SOURCE_KINH_DICH` (corpus lookup). Plus EXACTLY ONE composite envelope with `source_family = ReasoningEvidenceSourceFamily::Derived` and `source_id = "rule.composite.iching_consultation"`. The composite MUST NOT collapse the primitive sources. Never use bare source_id string literals at production call-sites — always go through `SOURCE_MAI_HOA_DICH_SO` / `SOURCE_KINH_DICH` consts.
- **No mutation of caller state:** `enrich_day_snapshot_with_iching(&DaySnapshot, IChingQuery)` takes `&DaySnapshot`, evaluates, clones, attaches the summary to the clone, returns the clone. The input snapshot's `iching_cast` field stays `None` after the call. Test asserts this.
- **No implicit IChing hour injection:** `calculate_day_snapshot(...)` MUST NOT invent an `IChingCastSummary`. The field stays `None`. Only an explicit `enrich_day_snapshot_with_iching()` call populates it.
- **WASM-safety + determinism (v1.7 carry-forward):** `rg "rand::|Utc::now|std::fs::" crates/amlich-core/src/iching/evaluator.rs` returns zero. No RNG, no wall-clock, no filesystem in `evaluator.rs`. Use runtime-built grep needles (mirror Plan 22-02's discipline).
- **No new crate dependencies:** The existing `Cargo.toml` already carries `serde`, `serde_json`, `chrono`, `unicode-normalization`. Do not add new crates.
- **Owned DTO data:** `IChingCastSummary` MUST own its serialised data — no `&'static HexagramEntry` references (those would tie the snapshot's lifetime to the OnceLock-cached corpus). Project the relevant `vi_name` / `thoai_tu` / `hao_tu` / `cat_hung` strings into owned `String` fields before storing on the summary. Same for evidence envelopes — own the `String`s.
</critical_constraints>
