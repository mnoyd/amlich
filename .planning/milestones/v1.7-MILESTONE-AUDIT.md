## v1.8+ Contract-Drift Risks (Advisory)

These are not gaps — they are advisory notes about where v1.8+ contracts could drift. Each has a mitigation test that would compile-break loudly.

1. **`add_iching_facts` consumes `DaySnapshot.iching_cast` (not recomputing)** — if `IChingCastSummary` field shape changes, builder at `day_snapshot.rs:807-861` must update. Mitigation: `iching_evaluator_uses_phase_22_surface_no_reimplementation` test compile-breaks.
2. **`add_direction_composite_facts` consumes `DaySnapshot.direction_cross_link`** — same risk if `DirectionCrossLinkSummary` fields renamed. Mitigation: `direction_cross_link_integration.rs` per-cell tests compile-break.
3. **`build_evidence` in `direction_composite.rs:582-626` hardcodes the huyen-khong method as runtime-built `"phi_tinh.palace_layout"`** — if the locked method name ever changes, both production + the test `assert_locked_evidence_shape` must update in lockstep. Mitigation: the test uses the same runtime-built needle pattern, so they cannot silently diverge.
4. **Stable-key shape `"iching:{role}:{king_wen}:{date}:{tz}"`** at `ids.rs:251-256` — if the format changes, role-bearing uniqueness (chu vs bien) must be preserved, otherwise `add_iching_facts` would emit duplicate `node_id`s and `SemanticGraph::add_node` would silently dedupe. Mitigation: `iching_graph_has_two_distinct_hexagram_nodes_when_enriched` test asserts `hex_nodes.len() == 2`.
