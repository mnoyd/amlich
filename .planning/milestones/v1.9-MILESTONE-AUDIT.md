# v1.9 Multi-dimensional Day, Hour, and Direction Assessment — Milestone Audit

**Milestone goal:** Deliver one explainable multi-dimensional assessment
system in which Day Assessment decides date suitability, Hour Ranking orders
the twelve hour slots downstream, and Direction Assessment orders relevant
directions. Existing almanac, personal non-Bazi, Bazi, timing, and feng-shui
signals must enter through typed, source-attributed observations without
duplicate influence or opaque lucky scores.

**Audited:** 2026-08-11

**Status:** `passed` — all seven requirements satisfied, all release gates
green, and no implementation gaps remain.

**Release head:** `8041b304fcc18e8c3307d66697f8d26223644da5`
(`feat(v1.9): explain conflicts, vetoes, dedup, and confidence`).

## Integration verification

1. Day Assessment, Hour Ranking, and Direction Assessment each own their own
   axes, contributions, availability, confidence, and warning semantics; the
   Direction result never mutates the Day decision bucket, and the Hour result
   never overrides an `Avoid` Day Assessment verdict.
2. `assessment/policy.rs` keeps every previous version constructible: `v2`,
   `v2.1`, `v2.2`, `v2.3`, and `v2.4` constructors return their original
   weight tables, so v1.7 / v1.8 fixtures remain byte-identical under the v2
   surface and v2.2 fixtures remain byte-identical under the v2.3 surface.
3. The explanation projection renders the same fields across core, API DTOs,
   TUI (`render_explanation_summary` in the `day_foundation` widget), and
   desktop `EvidenceGraph.svelte`; `explanation_cross_surface.rs` round-trips
   the projection through every consumer.
4. GitHub Actions runtimes no longer carry the Node 20 deprecation annotation;
   `actions/checkout@v6`, `actions/setup-node@v6`, and `pnpm/action-setup@v6`
   are the only versions referenced, and every workflow inputs
   `node-version: 24`.
