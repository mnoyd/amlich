# Research: Phase v1.2 - Ten Gods and Kua Foundation

**Phase:** v1.2-ten-gods-and-kua-foundation
**Research Date:** 2026-03-02
**Status:** Complete

---

## Executive Summary

Phase v1.2 can be planned as three parallel plans in Wave 1:

1. Ten Gods core engine and matrix tests (TT-01..TT-05)
2. Tu Menh/Kua calculator and fixture coverage (TM-01..TM-05)
3. DayFortune/public API integration and regression protection (INT-01..INT-06)

This work should follow existing v1.0/v1.1 patterns:
- typed enums/structs in `types.rs`
- deterministic pure helper functions
- table-driven tests
- serde-compatible fields and stable JSON shape

No external crates are required.

---

## Architecture Notes

- **Ten Gods**: place in new `crates/amlich-core/src/almanac/thap_than.rs`.
- **Kua**: place in new `crates/amlich-core/src/almanac/tu_menh.rs`.
- **Integration**: wire in `crates/amlich-core/src/almanac/calc.rs`, `crates/amlich-core/src/almanac/types.rs`, and public exports in `crates/amlich-core/src/lib.rs`.

Recommended type direction:

- `ThapThanLabel` enum for the 10 labels (Ty Kien, Kiep Tai, Thuc Than, Thuong Quan, Chinh Tai, Thien Tai, Chinh Quan, That Sat, Chinh An, Thien An)
- `ThapThanResult` struct containing label + evidence/source metadata hook
- `KuaGroup` enum (`East`, `West`)
- `KuaResult` struct with kua number, group, favorable/unfavorable directions, and conventions metadata

---

## Data and Rule Decisions

- Ten Gods mapping is deterministic from day stem polarity + five-element generate/control relationships.
- Matrix tests should explicitly cover 10 day stems x 10 target stems (100 cases).
- Kua should support representative year range 1900-2099 as required by TM-04.
- Edge behavior must be documented for year boundaries and convention choices (e.g., lunar-year interpretation assumptions).
- Dai Van is explicitly out of scope for v1.2 and must remain deferred.

---

## Risks and Mitigation

- **Risk:** wrong Ten Gods polarity mapping.
  - **Mitigation:** full 100-case matrix tests with explicit expected labels.
- **Risk:** Kua formula ambiguity across conventions.
  - **Mitigation:** lock one convention in docs/tests and include assumptions in code comments/doc section.
- **Risk:** accidental JSON/API breakage.
  - **Mitigation:** snapshot-style integration tests + full `cargo test --package amlich-core` gate.
