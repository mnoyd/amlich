Traditional Almanac Signal Processing: A Software Architecture and Decision Framework
The computational translation of traditional lunisolar almanac (tongshu/vạn sự) signals into a deterministic software architecture requires a rigorous decoupling of astronomical data generation from heuristic business logic. While the core engine successfully computes the underlying calendrical ephemerides—lunar phases, stem-branch (can-chi) interactions, solar terms (tiết khí), and lunar mansions (nhị thập bát tú)—the application of these signals to human activities relies on a complex, often contradictory matrix of historical texts and modern consensus.
This report provides an exhaustive, implementation-ready decision framework designed for integration into a Business Rules Management System (BRMS). The objective is to translate computed signals into actionable recommendation logic (nên làm, không nên làm, nên tránh, kiêng kỵ) using decoupled JSON-based rules engines.1 This architecture strictly avoids cultural storytelling, focusing exclusively on data normalization, hierarchical conflict resolution, schema design, and API output contracts to deliver deterministic, low-latency, and culturally safe daily recommendations.

A persistent challenge in almanac software design is the divergence between classical, highly granular doctrine and modern, flattened internet heuristics. 	Ranked List: Top 10 Implementation-Ready Signals
For an immediate software integration focusing on maximum computational precision, rapid execution, and high user trust, the following 10 signals offer the highest algorithmic determinism. These signals translate perfectly into boolean logic or highly weighted integers, avoiding the ambiguity of minor interpretative deities.
1. tu_tuyet (Tứ Tuyệt): Implementation-ready due to its strict mathematical predictability (exactly one day before the four seasonal nodes). It serves as a Tier 0 absolute global blocker.
2. tu_ly (Tứ Ly): Identical in structural predictability to Tứ Tuyệt, occurring one day before equinoxes and solstices. Evaluated as a Tier 0 boolean True/False blocker.
3. sat_chu (Sát Chủ): Highly deterministic, following a strict monthly branch mapping (e.g., Month 1 = Tỵ, Month 2 = Tý).8 Acts as a hard blocker specifically for construction, burial, and high-risk investments.
4. tam_nuong (Tam Nương): While classically debated, it is universally expected by modern Vietnamese users.8 It is purely mathematically derived from the lunar day integer (3, 7, 13, 18, 22, 27).
5. nguyet_ky (Nguyệt Kỵ): Derived directly from lunar day integers (5, 14, 23). Triggers specific UI warnings for travel and business operations.
6. truc (12 Kiến Trừ Thập Nhị Khách): The 12 Day Officers provide the most reliable algorithmic routing per category. Because the sequence is continuous and resets deterministically based on the month-branch 6, it forms the base_score matrix for all daily evaluations.
7. can_chi_xung (Tứ Hành Xung): The clash between the computed day branch and the user's birth branch (modulo 12 array logic). Essential for personalizing the API response and shifting from a generic calendar to a personalized engine.
8. hoang_dao_hac_dao (Hoàng Đạo / Hắc Đạo): Provides the hourly routing logic (Tier 4). Implementation is a direct array lookup matching the day's stem/branch to the six auspicious and six inauspicious hours.
9. can_chi_hop (Tam Hợp / Lục Hợp): The inverse of xung. A deterministic geometric relationship on the 12-branch wheel (120 degrees for trine, specific pairs for sextile) that provides a major positive multiplier for personalized queries.
10. tiet_khi (Tiết Khí): Solar terms provide the macro-boundaries for element shifting. While not a direct recommendation signal, it dictates the boundaries for calculating sat_chu and resetting truc, making it the highest-priority dependency in the data pipeline.

D. Conflict Resolution Framework
The central challenge in computational almanac processing is resolving contradictory signals. A day may simultaneously host a highly favorable major star and a moderately unfavorable minor demon. Simply summing these as raw integers leads to severe algorithmic drift, generating false positives and violating classical doctrine.
This framework strictly models the Quân Thần Tá Sứ (Ruler, Minister, Assistant, Courier) hierarchy derived from the Hiệp Kỷ Biện Phương Thư.4 It introduces an algorithmic implementation of Dĩ cát chế hung (Using the auspicious to suppress the inauspicious).
1. Precedence and Weighting Model (Prose Explanation)
Signals are assigned to distinct heuristic tiers. Evaluation is hierarchical, not purely additive. Higher-tier vetoes instantly short-circuit the execution path, drastically reducing compute cycles and ensuring safety.
* Tier 0: Absolute Taboos (The Void Layer)
   * Base Weight: -1000 (Hard Block)
   * Signals: tu_tuyet, tu_ly, nguyet_ky, tam_nuong, tho_tu, sat_chu.
   * Logic: If any Tier 0 signal triggers for the specific activity context, the day is mathematically unrecoverable. Execution stops. No amount of auspicious stars can salvage it. This satisfies the modern practitioner consensus.8
* Tier 1: Personal Relational Vetoes (The Clash Layer)
   * Base Weight: -500 (Hard Block for a specific user profile)
   * Signals: can_chi_xung (Clash), can_chi_hinh (Punishment).
   * Logic: Overrides all favorable signals only for the specific user experiencing the clash. A globally perfect day becomes TABOO for the clashing individual.
* Tier 2: Systemic Rulers (Quân - Major Stars/Trực)
   * Base Weight: +100 or -100
   * Signals: truc (12 Day Officers), Thái Dương (Great Sun), Nguyệt Đức (Lunar Virtue).
   * Logic: Functions as the baseline state vector of the day. A strong Tier 2 positive (e.g., +100) will actively suppress any negative Tier 3 or Tier 4 signals via the suppression engine.
* Tier 3: Ministers and Assistants (Thần / Tá - Minor Stars/Tú)
   * Base Weight: +50 or -50
   * Signals: nhi_thap_bat_tu (28 Mansions), secondary deity lists.
   * Logic: Additive modifiers. They shape the edges of the recommendation but mathematically cannot overturn a Tier 2 polarity.
* Tier 4: Couriers (Sứ - Hourly Modifiers)
   * Base Weight: +20 or -20
   * Signals: giờ hoàng đạo, giờ hắc đạo.
   * Logic: Applied conditionally to specific hours. They do not alter the day's global score but populate an array of optimal time windows.
2. Conflict Resolution Strategy (Pseudocode)
The following Python-like pseudocode demonstrates the DAG evaluation flow, specifically highlighting the Dĩ cát chế hung (suppression) logic.


Python




def evaluate_activity(date_signals, user_signals, activity_category):
   verdict_payload = {
       "score": 0, "status": "UNKNOWN", "rationale":, "evidence":
   }

   # 1. Evaluate Tier 0 (Global Hard Blocks)
   for signal in date_signals.get_tier(0):
       if signal.is_taboo_for(activity_category):
           verdict_payload["status"] = "TABOO"
           verdict_payload["score"] = -1000
           verdict_payload["rationale"].append(f"Absolute block triggered by {signal.name}")
           return verdict_payload # Short-circuit

   # 2. Evaluate Tier 1 (Personal Hard Blocks)
   if user_signals:
       if check_branch_clash(date_signals.can_chi, user_signals.can_chi):
           verdict_payload["status"] = "TABOO"
           verdict_payload["score"] -= 500
           verdict_payload["rationale"].append("Personal branch clash detected.")
           return verdict_payload # Short-circuit

   # 3. Evaluate Tier 2 (Systemic Rulers)
   tier_2_positives =
   for signal in date_signals.get_tier(2):
       weight = signal.get_weight_for(activity_category)
       verdict_payload["score"] += weight
       verdict_payload["evidence"].append(signal)
       if weight > 0: 
           tier_2_positives.append(signal)

   # 4. Evaluate Tier 3 (Ministers) with Suppression Logic
   for signal in date_signals.get_tier(3):
       weight = signal.get_weight_for(activity_category)
       
       # Suppression Engine: Dĩ cát chế hung
       if weight < 0 and len(tier_2_positives) > 0:
           suppressed = False
           for pos_sig in tier_2_positives:
               if pos_sig.can_suppress(signal.type):
                   suppressed = True
                   verdict_payload["rationale"].append(f"{signal.name} suppressed by {pos_sig.name}")
                   break
           if suppressed: 
               continue # Ignore the negative weight
           
       verdict_payload["score"] += weight
       verdict_payload["evidence"].append(signal)

   # 5. Final Verdict Mapping
   verdict_payload["status"] = map_score_to_status(verdict_payload["score"])
   return verdict_payload

def map_score_to_status(score):
   if score >= 100: return "RECOMMENDED"
   if score >= 30: return "FAVORABLE"
   if score >= -20: return "CAUTION"
   return "AVOID"

F. MVP Scope Proposal
Deploying a fully comprehensive rules engine capturing all 200+ distinct minor deities (thần sát) identified in the classical corpus introduces immense logic complexity, heavy computational overhead, and a high risk of heuristic contradictions that cannot be programmatically resolved. An agile, progressive release strategy is strictly required.
Minimal Credible v1 (Safe to Ship)
The primary objective of the v1 release is to provide mathematically flawless calendrical mappings and protect the user from widely recognized cultural taboos, ensuring immediate product safety and market credibility.
* Included Signals:
   * Tier 0 Global Taboos: tam_nuong, nguyet_ky, tu_tuyet, tu_ly, sat_chu, tho_tu.
   * Core Routing: truc (12 Day Officers), hoang_dao_hac_dao (Day and Hour level).
   * Basic Personalization: can_chi_xung (Year level branch clash only).
* Excluded/Deferred Signals:
   * nhi_thap_bat_tu (28 Mansions): Deferred to v2. While historically significant, modern applications often misinterpret their overlapping vectors with truc. The mapping array is massive and requires extensive QA.
   * Complex Thần Sát (Minor deities like Cẩu Giảo, Cô Thần): Deferred indefinitely. They introduce low-confidence heuristic noise that degrades the UI experience without adding actionable value.
   * Bát Tự / Tứ Trụ (Four Pillars): Deferred to v3. Requires complex five-element balancing algorithms outside the scope of daily signal mapping.
* Expected Limitations: The v1 system will exhibit a high rate of "Neutral" or "Caution" days due to the lack of secondary affirmative stars (Tier 3) to boost baseline scores. It operates defensively, prioritizing safety over aggressive recommendations.
* Roadmap for Expansion:
   * v2 (The Granularity Update): Integrate the 28 Mansions, mapping specific constellations to granular activities (e.g., separating contract_signing from business_opening). Introduce the full Dĩ cát chế hung suppression engine.
   * v3 (The Personalization Update): Integrate full birth-chart elemental analysis, transforming global almanac data into deeply personalized algorithmic recommendations based on exact birth hours.

	H. Initial Rule Pack for Core Activity Categories
To accelerate implementation, the following outlines the logical construction for three primary use cases in a format ready for translation into a rules engine.
Rule 1: Construction (Groundbreaking / Động Thổ)
* Condition 1 (Tier 0 Blocker): IF date IN (tu_tuyet, tu_ly, sat_chu, tam_sa_sat) -> RETURN TABOO, Score -1000.
* Condition 2 (Tier 1 Clash): IF user.can_chi_year IS xung WITH date.can_chi_day -> RETURN TABOO, Score -500.
* Condition 3 (Tier 2 Base Positive): IF date.truc IN (truc_binh, truc_man, truc_thanh) -> ADD +100.
* Condition 4 (Tier 2 Base Negative): IF date.truc IN (truc_kien, truc_pha, truc_be) -> SUBTRACT 100.
* Condition 5 (Tier 4 Modifier): IF date.is_hoang_dao == TRUE -> ADD +50.
* Evaluation Engine: Score > 100 (RECOMMENDED), Score > 30 (FAVORABLE), Score > -20 (CAUTION), Else (AVOID).
Rule 2: Life Event (Marriage / Cưới Hỏi)
* Condition 1 (Tier 0 Blocker): IF date IN (tam_nuong, nguyet_ky, tu_tuyet, tu_ly, kim_than_that_sat) -> RETURN TABOO, Score -1000.
* Condition 2 (Tier 1 Clash): IF user.can_chi_year IS xung WITH date.can_chi_day -> RETURN TABOO, Score -500.
* Condition 3 (Tier 2 Base): IF date.truc IN (truc_thanh, truc_khai) -> ADD +100.
* Condition 4 (Tier 3 Modifier): IF date.nhi_thap_bat_tu IN (sao_tam, sao_phong) -> ADD +50.
* Evaluation Engine: Strict adherence to absolute blockers. If day clears blockers but has score 0, flag as CAUTION (Requires deeper astrological reading of the Bát Tự).
Rule 3: Ritual (Burial/Funeral / An Táng)
* Condition 1 (Tier 0 Blocker): IF date IN (tho_tu, sat_chu, trung_tang) -> RETURN TABOO, Score -1000.
* Condition 2 (Tier 2 Base): IF date.truc IN (truc_tru, truc_pha) -> ADD +100. (Implementation Note: This rule requires an inversion of standard logic. Breaking/removal is highly positive for burial, while accumulation/fullness is highly negative).
* Evaluation Engine: Due to extreme cultural sensitivity 9, if score < 50, default the output payload's rationale string to advise consulting a specialized practitioner rather than outputting a generic AVOID.
I. Risks & Misinterpretation
Deploying algorithmic almanac logic into consumer software carries distinct product safety and user trust risks. The transition from computational ephemerides to heuristic recommendations is not purely mathematical; it is sociological.
1. Modeling Contradictory Traditions: The most severe risk lies in the divergence between classical texts (e.g., Hiệp Kỷ Biện Phương Thư) and modern practical almanacs. For example, modern Vietnamese practice strictly avoids Tam Nương and Nguyệt Kỵ for all major activities 7, while classical Qing-era imperial texts afford them little to no mathematical weight compared to astronomical solar terms.12
* Mitigation: The architecture must preserve this disagreement explicitly. The system enforces modern absolute taboos as Tier 0 blockers (honoring immediate user expectation and trust) while utilizing classical logic for the nuanced Tier 2/3 scoring matrix. Fake certainty must be avoided; if a day has conflicting parameters, the JSON response must output the exact rationale array detailing the source of the conflict.
2. Algorithmic Overconfidence and Drift:
A BRMS will mathematically process whatever array of facts it is fed. If a day evaluates to a massive +150 score merely because of stacked minor favorable stars (e.g., Tier 3/4), the UI might aggressively recommend a day that traditional practitioners know is structurally flawed due to an unmapped macro-pattern.
* Mitigation: Implement a hard ceiling on cumulative modifier scoring. No amount of Tier 3 or Tier 4 stars should be mathematically capable of bypassing a Tier 1 or Tier 0 blocker. The DAG architecture ensures short-circuiting prevents runaway addition.
3. Cultural Safety in Edge Cases (Yin vs. Yang States): Funeral logic (activity.ritual.burial_funeral) is profoundly sensitive.9 Recommending a day as "Highly Auspicious" for a funeral simply because of standard software string concatenation can deeply offend users and violate cultural norms.
* Mitigation: The system must implement specialized string overrides for the activity.ritual.* category tree. Instead of outputting "Auspicious" (Tốt / Cát), the translation layer mapping from the JSON payload must render "Appropriate" (Thích hợp) or "Safe" (An toàn). Fallback states for life-or-death categories must be excessively conservative, actively pointing users to human experts when the algorithmic confidence falls below 0.80.
